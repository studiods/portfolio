하이마트 UX 사례 디자인·콘텐츠 가이드 · V2.0

다섯 가지 글자 크기와
4px 간격 체계로
모든 사례를 정리합니다.

타이틀은 흰색 100%, 본문은 흰색 70%로 구분하고 블루·그린을 중심으로 사용합니다. 핵심 내용은 먼저 보이고 세부 근거는 관련 섹션의 ‘더 알아보기’에서 확인할 수 있게 구성합니다.

01 / 타이포그래피

글자 크기는 다섯 가지 역할로만
구분합니다.

크기를 계속 추가하지 않고 정보 위계에 맞는 역할을 선택합니다. 본문은 PC와 모바일 모두 16px을 유지하고, 주석만 12px을 허용합니다.

역할PC모바일사용 범위
첫 타이틀72–96px44–56px페이지 첫 화면의 프로젝트 핵심 문장 1개
대타이틀48–56px36px각 장의 결론형 제목, 핵심 데이터 숫자
중·소타이틀28px24px카드 제목, 소결론, 상세 콘텐츠 제목
본문16px16px설명, 카드 본문, 버튼, 표 본문
주석12px12px단계 라벨, 출처 성격, 범례, 보조 정보

가변 원칙: 원형·카드처럼 외형과 함께 줄어드는 텍스트는 해당 역할의 모바일 최솟값까지만 축소합니다. 그 이하 폭에서는 외형을 더 줄이지 않고 한 열 구조로 전환합니다.

02 / 간격

모든 간격은 4px의 배수로
같은 리듬을 만듭니다.

타이틀과 설명의 간격은 기존 20–24px에서 16px로 줄였습니다. 가까운 정보는 가깝게, 다른 논리 단계는 충분히 떨어뜨려 묶음이 먼저 보이게 합니다.

관계PC모바일적용 예시
라벨 → 타이틀16px16px‘03 / 실제 이용 행동’과 장 제목
타이틀 → 설명16px16px장 제목과 한두 문장 설명
소타이틀 → 본문16px16px카드 제목과 설명
설명 → 첫 콘텐츠64px48px장 도입부와 그래프·카드
관련 모듈 사이48px32px그래프와 결론, 결론과 상세 버튼
큰 하위 묶음 사이80–96px48–64px원칙 카드와 화면 예시
장과 장 사이160px96px01에서 02로 넘어가는 구간
카드 안쪽32–40px24px텍스트 카드와 데이터 카드
03 / 색상

흰색의 명도 차이와
세 가지 강조색만 사용합니다.

색을 장식으로 늘리지 않습니다. 타이틀과 본문의 명도 차이를 먼저 만들고, 블루·그린은 정보와 진행을, 레드는 실제 부정 신호만 표시합니다.

흰색 100%

타이틀

첫 타이틀, 장 제목, 카드 제목, 단계 라벨에 사용합니다.

흰색 70%

본문

제목 아래 설명, 카드 본문, 표 본문, 출처 성격에 사용합니다.

블루

정보·탐색

데이터 비교, 링크, 펼침 상태와 정보 흐름을 표시합니다.

그린

강점·연결

긍정 신호, 하이마트 강점, 개선 방향과 다음 단계를 표시합니다.

레드

부정 신호만

이탈·감소·불안과 같이 실제로 부정적인 값에만 좁게 사용합니다.

배경

검정 계열

검정과 짙은 회색 면만 사용해 정보의 밝기와 강조색이 먼저 보이게 합니다.

04 / 선과 그래프

구분선은 얇게,
데이터 선은 분명하게 만듭니다.

콘텐츠를 나누는 선과 데이터를 보여주는 선의 역할을 구분합니다. 표는 세로선을 사용하지 않아 행 단위로 읽히게 합니다.

종류규칙용도
기본 구분선1px · 흰색 14%섹션, 카드, 표의 행 구분
강한 구분선1px · 흰색 28%상단 메타 정보, 주요 구조의 시작
강조선4px · 블루/그린/레드핵심 결론이나 실제 부정 데이터의 시작
비율 막대8px 이상정성 분류 비중처럼 짧은 비교
주요 그래프12–16px유입 구성, 전후 변화, 단계별 증감
표가로선만 사용열은 정렬과 여백으로 구분하고 세로선은 제거
05 / 사례 구조

모든 사례는 같은 일곱 단계로
의사결정의 흐름을 보여줍니다.

프로젝트에 없는 단계를 억지로 채우지 않습니다. 다만 ‘왜 이 일을 했는가’와 ‘근거가 무엇이었는가’가 없는 결과 화면만 나열하지 않습니다.

06 / 한 화면 구성

한 화면에는 결론 하나,
근거 하나, 결정 하나만 둡니다.

채용 담당자나 리더가 제목과 그래프만 훑어도 사례의 논리가 이어져야 합니다. 세부 과정은 핵심 이해를 방해하지 않는 위치로 보냅니다.

요소기본 분량역할작성 기준
섹션 라벨1줄현재 논리 단계 안내03 / 실제 이용 행동처럼 한글로 명확하게 표기
결론형 제목PC 2줄, Mobile 3줄 이내스크롤을 멈추게 하는 핵심 주장“분석했습니다”가 아니라 “다음 행동이 끊겼습니다”처럼 결과를 먼저 씀
직접 설명2문장, 120자 안팎제목의 범위와 의미 보완새로운 주장 추가 금지. 제목을 해석하는 내용만 둠
핵심 시각화1개, 최대 4신호주장을 빠르게 확인축·범례를 읽어야만 이해되는 복합 그래프는 상세로 이동
설계 결정1문장근거가 실제 화면을 어떻게 바꿨는지 연결“그래서 홈을 다음 목적지 허브로 정의”처럼 동사로 끝냄
더 알아보기기본 닫힘과정·원수치·한계·세부 화면 보존핵심 결론을 접힌 영역에만 넣지 않음
07 / 근거에서 결정까지

숫자는 지표명이 아니라
사용자 행동으로 번역합니다.

데이터를 많이 보여주는 것이 데이터 드리븐이 아닙니다. 숫자가 무엇을 의미하고 어떤 결정을 바꿨는지까지 연결될 때 의사결정 근거가 됩니다.

01 · FACT

무엇이 일어났는가

“PDP +7.7%, 장바구니 −20.0%”처럼 계산 기준과 기간이 분명한 사실을 제시합니다.

02 · BEHAVIOR

고객은 무엇을 했는가

“상품은 더 봤지만 다음 단계로 덜 이동했다”처럼 누구나 이해하는 행동으로 바꿉니다.

03 · INTERPRETATION

어떤 가능성을 시사하는가

“관심 부족보다 구매 확신과 화면 연결을 점검할 신호”처럼 단정과 해석을 구분합니다.

04 · DECISION

무엇을 바꿨는가

“PDP 상단에 가격·리뷰·설치·매장 확인을 결정 요약으로 배치”처럼 설계 결정으로 끝냅니다.

권장 문장: “2026년 상반기 PDP 이용은 늘었지만 장바구니와 구매는 감소했습니다. 상품 관심이 사라진 것이 아니라 다음 판단을 끝내지 못했을 가능성을 확인했고, PDP의 역할을 ‘설명’에서 ‘결정 완료’로 바꿨습니다.”

근거 유형본문에 남길 것상세로 보낼 것주의
정성 자료반복되는 기대·불안 2–3개수집 채널, 분류 기준, 원문 예시정성 분류 비중을 시장 대표 통계처럼 표현하지 않음
행동 데이터설계 결정을 바꾼 변화 3–4개월별 값, 채널별 세부, 산식상관관계를 원인으로 단정하지 않음
동선 데이터반복되는 시작·종료 패턴전체 경로표, 추적 한계정확한 전환값이 아니면 ‘방향성 신호’로 명시
벤치마크차용한 학습 원칙비교 화면과 세부 패턴브랜드 UI를 복제했다는 인상을 주지 않음
08 / 시각화 선택

그래프는 분석의 난이도가 아니라
판단의 속도를 보여줘야 합니다.

한 그래프에서 한 질문만 답합니다. 고급 차트보다 비교 대상·방향·결론이 즉시 보이는 단순한 형태를 우선합니다.

구성 비율

유입 구성

100% 누적 막대로 표현합니다. 채널은 4개 이내로 묶고 숫자는 직접 표기합니다.

전후 비교

기간 변화

두 시점의 막대 또는 큰 숫자를 사용합니다. 작은 월별 변동은 상세로 이동합니다.

다음 단계

다음 단계 연결

단계별 증감 또는 짧은 퍼널을 사용합니다. 서로 다른 모집단이면 퍼널 전환율처럼 보이지 않게 합니다.

기기별 역할

기기별 차이

동일한 기준을 좌우로 비교하고 “모바일=탐색, PC=비교”처럼 역할 차이를 함께 씁니다.

고객 의견

의견 묶음

키워드 클러스터와 짧은 막대를 사용합니다. 워드클라우드는 단어 크기 의미가 명확할 때만 씁니다.

사용 지양

복잡한 흐름·다중축

핵심 본문에서는 피합니다. 반드시 필요하면 단순 결론을 먼저 두고 원본을 상세에 제공합니다.

09 / 단계적 상세

먼저 이해시키고,
원하는 사람에게 깊이를 제공합니다.

긴 내용을 삭제하는 대신 우선순위를 정합니다. 핵심 결론은 항상 보이고, 검증 과정과 원자료는 해당 결론 바로 아래에서 펼쳐봅니다.

항상 보임더 알아보기별도 원자료
문제·핵심 발견·설계 결정분석 과정·세부 수치·대안 비교전체 대시보드·원본 리포트·부록
대표 그래프 1개월별·기기별·채널별 보조 그래프원데이터 테이블과 산식
대표 화면과 적용 이유화면별 상세 요구사항전체 프로토타입·명세
내 역할과 결정협업 과정·검증 질문·변경 이력회의 자료·리서치 기록

`더 알아보기`는 섹션마다 가까이 둡니다. 페이지 끝에 모든 상세를 몰아두면 어떤 결론의 근거인지 다시 찾아야 하기 때문입니다. 네이티브 <details>/<summary> 또는 동일한 키보드·상태 안내를 지원하는 아코디언을 사용합니다.

10 / UX 리드의 역할

시니어의 가치는 산출물 수가 아니라
판단의 질로 보여줍니다.

프로젝트마다 리더가 바꾼 기준과 선택을 네 가지 역할로 명시합니다. 역할명만 쓰지 않고 실제로 무엇을 결정했는지 붙입니다.

문제 정의

문제를 다시 정의

요청을 그대로 실행하지 않고 고객·사업·데이터 관점에서 풀어야 할 범위를 재설정합니다.

우선순위

중요한 신호를 선택

모든 요구와 데이터를 나열하지 않고 의사결정을 바꾸는 증거에 우선순위를 둡니다.

기준 정렬

팀의 기준을 통일

화면별 역할, 정보 위계, 컴포넌트와 측정 기준을 PO·디자인·개발이 같은 언어로 사용하게 합니다.

검증

학습을 다음 반복으로

프로토타입과 내부·사용자 검증 결과를 수정 목록, 이벤트 태깅, 개선 백로그로 연결합니다.

11 / 문장 규칙

전문 용어보다 행동을 쓰고,
결과보다 근거를 앞세웁니다.

읽는 사람이 프로젝트 배경을 모른다고 가정합니다. 화면명과 지표명만으로 설명하지 말고, 고객이 무엇을 하려 했고 어디서 어려웠는지 씁니다.

피해야 할 표현권장 표현이유
“데이터를 분석했습니다.”“상품은 더 봤지만 장바구니로 덜 이동했습니다.”분석 행위보다 발견을 먼저 전달
“홈 UX를 고도화했습니다.”“홈을 콘텐츠 진열장이 아니라 다음 목적지 허브로 바꿨습니다.”화면의 역할 변화가 보임
“네이버·쿠팡 UI를 적용했습니다.”“익숙한 탐색·구매 문법을 활용해 재학습 비용을 줄였습니다.”복제보다 학습 원칙을 강조
“옴니채널을 강화했습니다.”“온라인 비교를 매장 상담으로 넘기고, 매장 경험을 온라인 구매로 이어줬습니다.”추상어를 실제 행동으로 번역
“전환율 개선이 기대됩니다.”“PDP→장바구니 연결률을 출시 후 핵심 지표로 재검증합니다.”근거 없는 성과 단정 대신 측정 계획 제시
12 / 적용 체크리스트

시각 규칙은 기존 Portfolio Editorial Design Guide를 함께 사용하고, 이 체크리스트는 이야기의 논리와 정보량을 점검합니다.

  • 첫 화면만 보고 프로젝트 문제·내 역할·범위를 이해할 수 있는가
  • 요청받은 과제와 실제로 재정의한 문제가 구분되어 있는가
  • 정성 신호와 정량 행동이 각각 하나의 결론으로 압축되어 있는가
  • 정성+정량이 만나는 핵심 문제를 한 문장으로 말할 수 있는가
  • 핵심 본문에 설계 결정을 바꾸지 않는 데이터가 남아 있지 않은가
  • 모든 숫자에 기간·단위·비교 기준이 있는가
  • 사실·해석·가설·성과가 서로 다른 문장으로 구분되어 있는가
  • 그래프를 보자마자 비교 대상과 방향을 알 수 있는가
  • 화면별 역할이 “사용자가 끝내는 판단”으로 쓰였는가
  • 벤치마크는 차용한 원칙과 하이마트만의 차이를 함께 설명하는가
  • 매장·상담·설치·회수·케어 강점이 구매 여정 안에 연결되어 있는가
  • UX Lead의 Frame·Prioritize·Align·Validate 결정이 보이는가
  • 상세 내용은 관련 결론 바로 아래 `더 알아보기`에 있는가
  • 핵심 결론이 접힌 콘텐츠 안에만 들어가 있지 않은가
  • PC와 모바일에서 제목 줄수·그래프·표가 가로 스크롤 없이 읽히는가
