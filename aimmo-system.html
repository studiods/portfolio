디자인 시스템 구축으로 시작했지만,
결국 전체 업무 시스템을 개선했습니다.

사용자와 업무 환경, 팀의 반복 업무를 함께 분석해 가장 필요한 기준부터 순차적으로 구축했습니다.

01

파악해 보니,
같은 일을 계속 반복하는 것이 더 큰 문제였습니다.

디자인·개발 모두 반복 생산이 일상이었고, 공통 기준도 부족했습니다.

01.1

먼저 팀원들로부터 히스토리를 파악했습니다.

팀이 왜 시스템을 만들지 못했고 어떤 불편을 반복해왔는지부터 확인했습니다.

“시간이 없어 공통 디자인 에셋도 못 만들었어요.”RESOURCE
“UX를 조금만 바꿔도 불편함을 호소해서 손을 못 대요.”UX CHANGE
“비슷한 기능인데 서비스마다 UX가 달라 불편하다는 이야기가 많아요.”CONSISTENCY
“디자인 시스템을 만든 경험이 없어 어떻게 시작해야 하는지 모르겠어요.”STARTING POINT
“한 번에 전체 적용을 못하면 계속 화면이 달라질 것 같아요.”ADOPTION
“회사에서 왜 필요한지 공감대를 만들기 어려웠어요.”ALIGNMENT

결국 경험과 시간 부족, 단계 적용의 어려움, 조직의 공감대 부족이 함께 얽혀 있었습니다.

디자인 시스템 자체보다 시작하고 적용하고 유지할 수 있는 업무 구조가 먼저 필요했습니다.

문제는 디자인팀만이 아니었습니다.
디자인과 개발 모두 반복 작업을 계속하고 있었습니다.

같은 기능을 설계·전달·구현·확인하는 과정이 제품마다 다시 시작됐습니다.

01.3

그래서 목표를 디자인 시스템 제작에서,
디자인·개발 프로세스와 협업 방식 정립으로 확장했습니다.

산출물 전달부터 토큰·라이브러리 운영까지 재사용 가능한 협업 구조로 바꿨습니다.

01

반복되는 기준부터 정리했습니다.

컴포넌트·상태·예외처럼 매번 다시 판단하던 항목을 공통 기준으로 묶었습니다.

02

산출물을 재사용 가능한 구조로 바꿨습니다.

화면 단위 전달보다 컴포넌트와 상태 단위로 정리해 다음 제품에서도 다시 쓸 수 있게 했습니다.

03

개발 전달 방식도 표준화했습니다.

속성·상태·예외를 같은 구조로 전달해 화면마다 다시 설명하는 비용을 줄였습니다.

04

디자인과 개발 토큰을 맞췄습니다.

컬러·타이포·간격·Radius 같은 공통 값을 개발 토큰과 매핑해 같은 기준을 보게 했습니다.

05

공통 리소스를 라이브러리화했습니다.

디자인과 개발 양쪽에서 재사용할 수 있도록 핵심 컴포넌트와 토큰을 라이브러리로 관리했습니다.

06

변경과 리뷰 방식까지 운영 체계로 만들었습니다.

버전·리뷰·변경사항 공유 규칙을 정해 시스템이 실제 업무 안에서 계속 유지되게 했습니다.

02

만들기 전에,
실제 사용자들의 업무 방식과 환경부터 분석했습니다.

정확성과 속도가 생산성으로 이어져 화면보다 업무 환경과 행동을 먼저 봤습니다.

02.1

직접 묻고,
옆에서 실제 업무를 관찰했습니다.

사용 환경·조도·작업 시간을 인터뷰하고 Shadow Tracking으로 실제 흐름을 확인했습니다.

02.2

사용성의 핵심은,
빠르고 정확한 판단이었습니다.

Crowd Worker 특성상 탐색·판단·실행 시간을 줄이는 것이 생산성과 직결됐습니다.

01 / ENVIRONMENT

사무실과 재택 환경

회사뿐 아니라 집에서 장시간 작업하는 환경도 고려했습니다.

02 / DURATION

오래 지속되는 작업

장시간 작업 구간에서 불필요한 밝기와 장식을 줄였습니다.

03 / DECISION

빠른 상태 판단

상태 컬러와 정보 위계를 명확히 해 판단을 빠르게 이어가게 했습니다.

04 / OUTPUT

시간당 처리 생산성

선택지를 줄여 탐색과 실행의 인지 부담을 낮췄습니다.

02.3

환경과 사용 패턴을 분석해 보니,
수많은 개선 포인트를 발견했습니다.

다크 모드를 정답으로 두지 않고, 저조도·장시간 사용 환경과 관련 연구를 함께 검토했습니다.

01 / DARK MODE

다크 모드로 전환이 필요했습니다.

작업자 상당수가 가정의 낮은 조도에서 장시간 작업했습니다. 실제 관찰과 저조도 환경에서 dark mode의 시각 피로가 더 낮게 나타난 연구를 함께 참고해 전체 luminance를 낮췄습니다.

02 / COLOR

컬러도 다시 조정했습니다.

행동·상태 대비를 명확히 해 눌러야 할 것과 그렇지 않은 것을 즉시 구분하도록 했습니다. 가장 많이 사용하던 삼성 노트북 환경을 기준으로 실제 화면을 반복 확인하며 컬러를 보정했습니다.

03 / COMPONENT SCALE

컴포넌트 크기도 다시 설정했습니다.

주요 모니터·노트북 환경을 비교해 버튼 크기, Radius, 폰트 크기와 간격을 다시 조정했습니다. 장시간 작업에서도 빠르게 찾고 정확히 누르는 것을 기준으로 삼았습니다.

04 / GRAPHIC & BRANDING

그래픽 스타일과 브랜딩 요소도 통일했습니다.

아이콘·메타포의 표현 방식을 통일하고, 시각적 임팩트를 주는 브랜드 컬러는 Violet 한 톤으로 정리했습니다. 서로 다른 제품도 하나의 브랜드에서 출발한 서비스로 인식되게 했습니다.

SOURCE · 기존 포트폴리오 / 사용자 관찰·디스플레이 환경 점검 · RESEARCH CONTEXT · Xie et al., 2024, Effects of Screen Color Mode and Color Temperature on Visual Fatigue · WCAG contrast guidance

04 / PACKAGE

2~3개 제품 패키지

03.4

디자인에서 끝내지 않고,
개발까지 같은 기준으로 연결했습니다.

개발 과정의 막힘을 지속적으로 확인하고 필요한 정의를 빠르게 보완했습니다.

01 / INTERVIEW

실제 개발 과정의 부족한 지점을 확인했습니다.

디자인 정의와 구현 사이의 차이를 빠르게 수집했습니다.

02 / LIBRARY

재사용 가능한 구조로 라이브러리화했습니다.

같은 기능을 다시 만드는 비용을 줄였습니다.

03 / TOKEN

공통 값을 토큰으로 연결했습니다.

디자인과 개발이 같은 기준을 바라보게 했습니다.
