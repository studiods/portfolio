01

화면을 그리기 전에,
누가 어디서 어떻게 쓰는지부터 정의했습니다.

호텔·모텔 운영 시스템은 현장 생산성과 실수 방지가 핵심이었습니다.

01.1 / BEFORE SYSTEM

디자인 시스템을 만들기 전,
항상 네 가지 질문부터 시작했습니다.

서비스 성격, 전달 가치, 사용 환경, 일관된 경험 조건을 먼저 확인했습니다.

우리 서비스가 가진

사용자에게 전달하는가?

사용자는 어떤 환경과 조건에서
서비스를 사용하는가?

통일되고 일관된
사용자·브랜드 경험을 제공할 수 있는가?

SOURCE - 신동식 Portfolio / HST GROUP DESIGN SYSTEM, p.48
01.2 / ANSWERS

질문에 대한 답은 명확했습니다.
‘잘 보이는 화면’보다 ‘일을 더 정확하고 빠르게 하는 시스템’이 필요했습니다.

호텔·모텔 B2B 제품군의 핵심 가치를 명확성·효율성·생산성·신뢰로 정리했습니다.

01 / SERVICE CHARACTER

24시간 운영되는
호텔·모텔 프론트 업무 도구

예약과 객실 상태, 고객 요청을 반복해서 확인하고 처리하는 운영 시스템입니다. 화면은 감상하는 대상이 아니라 즉시 판단하고 실행하는 업무 도구여야 했습니다.

02 / CORE VALUE

명확성 · 효율성 · 생산성이
브랜드 인상보다 먼저였습니다.

고객 응대 중에도 상태와 다음 행동을 빠르게 파악하고 실수를 줄여야 했습니다. 그래서 디자인의 역할을 업무 처리 속도와 정확도를 높이는 것으로 정의했습니다.

03 / FIELD CONDITION

앉아서 오래 보는 화면이 아니라,
계속 시선이 끊기는 환경이었습니다.

프론트는 고객 응대와 이동이 반복되고 주변 조도도 일정하지 않습니다. 따라서 중요한 예약·객실·상태 정보는 짧은 시선에도 바로 구분되는 주목도와 시인성이 필요했습니다.

04 / PRODUCT FAMILY

4~5개 제품이 함께 팔려도,
같은 가족이면서 각각 구분돼야 했습니다.

공통 UX와 핵심 컴포넌트는 유지하되 제품별 컬러와 일부 주요 컴포넌트를 특성화해 같이 보이면서도 다르게 인지되는 제품 패밀리를 만들고자 했습니다.

01.3 / FIELD CONTEXT

근무자에게서 수집한 환경 조건을 바탕으로,
실제 프론트에서 놓치지 않는 정보 체계를 만들었습니다.

연령·역할, 모니터, 조도, 업무 자세와 이동 패턴을 디자인 기준으로 전환했습니다.

01 / USER

연령과 역할

실제 근무자의 연령과 담당 업무를 고려해 정보 밀도와 표현 방식을 판단했습니다.

02 / DISPLAY

모니터와 해상도

업무용 PC 환경에서 작은 텍스트와 상태 정보가 뭉개지지 않도록 확인했습니다.

03 / LIGHT

조도와 대비

로비와 야간 근무처럼 주변이 어두워져도 주요 상태의 대비가 유지되도록 설계했습니다.

04 / MOVEMENT

이동과 고객 응대

앉아 있는 시간보다 시선이 끊기는 순간을 고려해 핵심 정보의 위치와 크기를 고정했습니다.

05 / GLOBAL

색각과 문화 차이

색상 하나에 의미를 맡기지 않고 밝기·텍스트·형태를 함께 사용했습니다.

SOURCE - 신동식 Portfolio p.48, 현장 근무자 기반 환경 정보 / RESEARCH REFERENCE - EN 12464-1: reception/cashier desk 300 lx · WCAG 2.1 Use of Color
01.4 / SYSTEM DIRECTION

그래서 디자인 시스템을
‘같은 화면을 만드는 규칙’이 아니라 ‘같은 품질의 업무를 만드는 기준’으로 정의했습니다.

공통성을 유지하면서 제품별 특성을 더해, 신뢰할 수 있는 시스템을 목표로 했습니다.

01 / CLARITY

한눈에 상태를 읽는 명확성

예약·객실·알림의 우선순위를 짧은 시선에도 구분합니다.

02 / EFFICIENCY

반복 업무를 줄이는 효율성

같은 행동은 같은 위치와 패턴으로 반복해 학습 비용을 줄입니다.

03 / FAMILY

같이 보이되 다르게 구분

공통 컴포넌트 위에 제품별 컬러와 특화 요소를 더합니다.

04 / TRUST

실수 없이 믿고 쓰는 안정감

형태·대비·피드백을 일관되게 유지해 시스템 신뢰를 만듭니다.

02

제작 방향을 명확히 하고,
세 가지 목표로 시스템을 압축했습니다.

직관성, 글로벌 확장성, 제품 간 일관성을 공통 판단 기준으로 잡았습니다.

02.1 / THREE GOALS

빠르게 이해하고, 어디서나 쓰고,
제품이 달라도 같은 경험을 주는 것을 목표로 했습니다.

01 / CLARITY

직관적이고 명확한 형태와 색상

근무자가 빠르게 상황을 파악하고 대응하도록 시인성과 정보 인지성을 높였습니다.

02 / GLOBAL

글로벌 표준을 위한 범용 설계

국가·언어·색각·환경 차이를 고려해 해외에서도 동일한 정보 계층을 느끼도록 했습니다.

03 / CONSISTENCY

일관된 사용성과 브랜드 경험

각 제품이 하나의 경험처럼 이어지도록 공통 요소와 제품별 특성화 요소를 함께 정의했습니다.

SOURCE - 신동식 Portfolio / HST GROUP DESIGN SYSTEM, p.49
02.2 / TRANSLATE

목표는 추상적인 슬로건이 아니라,
실제 화면에서 판단할 수 있는 규칙으로 바꿨습니다.

빠른 인지, 환경 대응, 일관된 UX를 컬러·형태·타이포·컴포넌트에 연결했습니다.

CLARITY → VISIBILITY

상태와 행동의 우선순위를 색과 대비로 명확히 했습니다.

짧은 시간 안에 상태를 판단해야 하는 B2B 업무 흐름을 기준으로 삼았습니다.

GLOBAL → ACCESSIBILITY

색각과 환경 변화에서도 동일한 강조 수준을 전달했습니다.

색만이 아니라 명도, 텍스트, 형태와 상태 변화가 함께 정보 위계를 만들도록 했습니다.

CONSISTENCY → COMPONENT

반복되는 기능은 같게, 제품의 개성은 다르게 설계했습니다.

공통 컴포넌트는 공유하고 제품별 컬러·특화 컴포넌트로 패밀리 안의 구분감을 만들었습니다.

라운드 값 하나, 대비 한 단계도

02 / ACTION HIERARCHY

주요 행동은 채움과 대비로, 보조 행동은 외곽선으로 빠르게 구분했습니다.

확인과 취소가 가까이 있을 때도 시선이 Primary에 먼저 도달하도록 중심 정렬과 여백, 채움 정도를 달리했습니다. 삭제처럼 위험한 행동은 별도 색과 간격을 사용했습니다.

03 / CONTRAST BASELINE

밝거나 어두운 근무 환경에서도 중요한 경계와 텍스트가 사라지지 않게 했습니다.

WCAG 2.1의 텍스트 4.5:1, UI 식별 요소 3:1 기준을 최소 검토선으로 삼고, 실제 화면에서는 상태 중요도에 따라 더 큰 명도 차이를 사용했습니다.

04.3 / RESULT

UX디자인팀 리드로서 디자인 시스템을
‘디자이너를 위한 라이브러리’가 아니라 ‘제품 목적성과 생산성을 높이는 운영 기준’으로 만들었습니다.

문제 정의부터 환경 분석, 원칙 도출, 컴포넌트 실행까지 전체 흐름을 디렉팅했습니다.

01 / DEFINEPROBLEM

제품마다 달라지는 화면이 아니라 현장 업무의 속도와 정확도를 문제로 정의했습니다.

02 / OBSERVECONTEXT

근무자, 모니터, 조도, 이동과 고객 응대까지 실제 사용 조건을 수집했습니다.

03 / TRANSLATEPRINCIPLE

명확성·효율성·글로벌 접근성·제품 패밀리를 디자인 원칙으로 전환했습니다.

04 / DIRECTEXECUTION

컬러·형태·타이포·컴포넌트가 같은 목적을 향하도록 기준과 디테일을 조율했습니다.

05 / SYSTEMIZEPRODUCTIVITY

반복 업무와 판단 차이를 줄여 제품 개발과 운영의 생산성을 높이는 시스템으로 정리했습니다.

UX DESIGN LEAD → PRODUCT SYSTEM DIRECTION

디자인 시스템의 목적은 화면을 통일하는 데 있지 않았습니다.
현장 근무자가 더 빠르고 정확하게 일하고, 여러 제품이 하나의 신뢰 가능한 제품군으로 작동하도록 만드는 것이 목표였습니다. 그 관점에서 문제 정의부터 적용 방법, 실행과 정리까지 전 과정을 리드했습니다.
