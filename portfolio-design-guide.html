PORTFOLIO EDITORIAL SYSTEM · V1.0

내용의 위계를 먼저 읽고,
같은 간격과 글자 규칙으로
다시 만들 수 있게 합니다.

하이마트 구매여정 페이지에서 실제 사용 중인 요소를 분석해 타이포그래피, 간격, 라인, 컬러, 반응형 규칙을 범용 토큰으로 정리했습니다. 프로젝트별 표현은 달라져도 정보 위계와 읽기 리듬은 같은 체계를 사용합니다.

01 / PRINCIPLES

숫자보다 먼저
간격의 의미를 고정합니다.

동일한 20px이라도 제목과 설명 사이인지, 카드 안쪽 여백인지에 따라 의미가 다릅니다. 모든 값은 역할 이름으로 사용하고 직접 숫자를 입력하는 것은 예외로 제한합니다.

RELATIONSHIP가까울수록 같은 의미

제목과 설명은 12–20px, 한 모듈의 구성 요소는 20–48px 안에서 묶습니다.

HIERARCHY위계가 커질수록 더 넓게

모듈 56–80px, 중단락 80–120px, 장 120–200px 순으로 간격을 키웁니다.

RESPONSIVE역할은 같고 값만 변화

PC와 모바일에 별도 의미를 만들지 않고 같은 토큰이 화면 폭에 따라 다른 값을 가집니다.

READABILITY본문은 장식보다 읽기 우선

본문은 16px·1.62행간을 기본으로 하고, 한 줄 길이는 약 44em 이내로 제한합니다.

EXCEPTION데이터는 고정값을 강요하지 않음

원형·차트·대형 숫자는 컨테이너에 반응하되 각 역할별 최소 글자 크기를 지킵니다.

ACCESSIBILITY200% 확대와 재배치 전제

텍스트 확대 시 잘림과 양방향 스크롤이 없어야 하며 모션 감소 설정을 지원합니다.

04 / RESPONSIVE TYPE

외형에 묶인 글자는
컨테이너가 크기를 결정합니다.

원형 카드처럼 외형 크기가 달라지는 요소는 화면 폭이 아니라 실제 컨테이너 폭을 기준으로 합니다. 제목 16px, 본문 12px, 수치 20px을 절대 하한으로 두며 그 이하가 필요하면 글자를 더 줄이지 않고 레이아웃을 바꿉니다.

06 / COLOR

블루가 구조를 이끌고,
나머지는 의미가 있을 때만 씁니다.

07 / LAYOUT & BEHAVIOR

1440px 화면 안에서
1280px 콘텐츠 폭을 사용합니다.

PC는 최대 1280px 콘텐츠와 32px 최소 거터, 모바일은 16–22px 거터를 사용합니다. 긴 본문은 약 44em으로 제한하고 780px 이하에서는 의미 단위가 유지되도록 1열 또는 세로 흐름으로 전환합니다.

08 / PAGE CHECKLIST

새 페이지를 만들 때
아래 항목만 먼저 확인합니다.

프로젝트별 새 CSS 값을 추가하기 전에 기존 역할 토큰으로 해결되는지 확인합니다. 예외는 외형 크기에 종속된 데이터 시각화나 고유한 인터랙션에 한해 기록합니다.

  • 페이지 제목은 Display 한 번만 사용했는가
  • 대·중·소 제목의 역할이 서로 뒤바뀌지 않았는가
  • 제목→설명 간격은 20/16 또는 16/12 토큰인가
  • 중단락 간격은 120/80 토큰인가
  • 제목은 White 100%, 직접 설명은 White 56%로 통일됐는가
  • 제목과 설명의 크기 비율이 최소 1.4:1 이상인가
  • 본문은 16px·1.62, 모바일 최소 15px 이상인가
  • 한 줄 본문이 44em 또는 약 75자를 넘지 않는가
  • 출처는 11–12px이며 핵심 정보를 담지 않는가
  • 구분선은 10·14·30% 중 의미에 맞는가
  • 3px 컬러 라인은 실제 강조 의미가 있는가
  • 블루 외 컬러가 장식 목적으로 남용되지 않았는가
  • 원형·차트 텍스트가 최소값 아래로 내려가지 않는가
  • 320px 폭에서 페이지 가로 스크롤이 생기지 않는가
  • 200% 확대 시 텍스트가 잘리거나 겹치지 않는가
  • 키보드 포커스와 reduced-motion이 동작하는가
