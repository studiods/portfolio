# Reuse 신뢰 운영 기준 — 작업 초안

> 상태: 공개된 `himart-reuse.html` 사례를 실제 운영 요건으로 풀어 쓴 포트폴리오 작업 초안입니다. 롯데하이마트의 확정된 등급·검수·보증·반품 정책을 뜻하지 않습니다. **확정 필요** 항목은 담당자가 정책과 근거를 확인하기 전까지 운영에 적용하지 않습니다.

## 1. 목적과 근거 원칙

고객이 중고가전 구매 전에 확인하려는 실물 상태, 기능, 세척, 보증, 판매 책임, 배송·설치 정보를 각각 확인 가능한 증거와 연결합니다. 고객에게 표시하는 모든 주장은 개별 상품 기록, 승인된 정책 또는 기록된 작업에 근거해야 합니다. 증거가 없는 상태를 템플릿 문구로 '검증 완료'처럼 표시하지 않습니다.

이 문서는 공개 사례 페이지에 이미 설명된 범위만 사용합니다. 설문 원자료, CRM 행, 내부 보고서와 개별 상품 기록은 포함하지 않습니다.

## 2. Trust Risk Matrix

| 고객의 질문 | 필요한 근거 | 확인 지점 | 근거가 없을 때 |
| --- | --- | --- | --- |
| 사진과 실제 받을 제품이 같은가? | 상품 ID에 연결된 실사진, 흠집, 상태 요약, 촬영일 | 목록 미리보기와 구매 전 PDP | 사진과 상품 ID가 일치할 때까지 게시 보류 |
| 정상 작동하며 무엇을 수리했는가? | 카테고리별 검수 항목·결과·일자, 해당 시 수리·교체 기록 | PDP의 상태·검수 영역 | 미검수 결과를 합격으로 표시하지 않음 |
| 청결과 위생을 확인할 수 있는가? | 실제 세척 단계와 확인 기록 | PDP의 상태 영역 | 확인되지 않은 세척 문구를 제외하고 검토 요청 |
| 고장이 나면 누가 책임지는가? | 현재 보증·반품·서비스 조건과 책임 주체 | PDP와 결제 | 승인된 약관만 표시하고 충돌하는 약속은 게시 보류 |
| 내 지역에 배송·설치할 수 있는가? | 상품별 가능 지역, 비용, 설치 범위와 제약 | 목록, PDP, 결제 | 결제 전에 가능 여부 확인 |
| 저장된 개인정보가 제거되었는가? | 데이터 저장 기능이 있는 제품의 삭제 검증 기록 | 해당 카테고리의 PDP | 기록 없이 삭제 완료라고 주장하지 않음 |

상품, 검수, 콘텐츠, 정책, 배송·서비스 영역의 실제 책임 담당자와 예외 처리자는 **확정 필요**입니다. 각 근거 필드에는 한 명의 최종 책임자를 지정합니다.

## 3. Trust Experience Blueprint

| 단계 | 고객 행동 | 최소 신뢰 정보 | 운영 데이터 연결 |
| --- | --- | --- | --- |
| 탐색·목록 | 구매 가능한 후보 찾기 | 실물 사진 여부, 상태 요약, 배송 가능 여부 | 재고 기록 → 목록 |
| PDP: 동일 상품 확인 | 이 상품의 실제 상태 확인 | 실사진 갤러리, 흠집, 등급 기준 | 촬영 기록 + 등급 정책 버전 → PDP |
| PDP: 구매 판단 | 기능과 사용 위험 판단 | 검수·세척 근거, 승인된 보증·판매 주체 | 검수 결과 + 정책 기록 → 신뢰 모듈 |
| 결제 | 최종 조건 확인 | 상품 식별, 총액, 배송·설치, 반품·보증 조건 | PDP 표시값 → 주문 기록 |
| 배송·사후관리 | 수령하고 문제 해결 | 상품 이력, 문의 창구, 적용 보증 | 주문 + 근거 보관본 → 고객 지원 |

게시 후 정책이나 상품 기록이 바뀌면 PDP와 결제 화면에 같은 최신 버전을 사용합니다. 주문 시 고객에게 제시한 조건은 사후 문의를 위해 주문 기록에 남겨야 합니다.

## 4. 최소 메타데이터 스키마

| 필드 | 의미 | 기준 시스템 | 게시 조건 |
| --- | --- | --- | --- |
| `item_id`, `category_code` | 실물 상품과 카테고리 | 재고 | 필수. 모든 근거가 같은 상품에 연결되어야 함 |
| `condition_grade_code`, `grade_policy_version` | 등급과 판정 기준 버전 | 승인된 등급 정책 | 등급 표시 시 필수. 구체적 임계값은 **확정 필요** |
| `cosmetic_defects` | 흠집의 위치·종류·정도와 연결 사진 | 검수·촬영 | 필수. 기록된 흠집이 없을 때도 명시적 상태 필요 |
| `functional_checks`, `inspection_at` | 검수 항목별 합격·불합격·미검수와 일시 | 검수 | 필수. 미검수를 합격으로 합치지 않음 |
| `repair_history` | 해당 상품의 수리·부품 교체 | 서비스·검수 | 해당 시 필수. 기록 없음과 확인 불가 구별 |
| `cleaning_record` | 수행한 세척 단계·일자·확인 결과 | 상품화 운영 | 세척을 주장할 때 필수 |
| `photo_asset_ids`, `captured_at` | 실물 사진과 촬영 일시 | 미디어 관리 | 필수. 모든 파일이 `item_id`에 연결되어야 함 |
| `warranty_policy_id`, `seller_id` | 적용 약관과 판매 책임 주체 | 정책·판매자 관리 | 보증·판매자 문구 표시 시 필수 |
| `delivery_install_scope` | 가능 지역·비용·일정·설치 제약 | 배송·설치 | 결제 가능 여부 판단 전에 필수 |
| `data_wipe_record` | 데이터 저장 제품의 삭제 결과·일시 | 승인된 검수 | 해당 카테고리에만 필수. 기록 없이 주장 금지 |
| `qa_state`, `published_at` | 검토 상태와 현재 게시 시각 | 콘텐츠 운영 | 게시·수정 이력 관리에 필수 |

고객 노출 문구는 승인된 근거와 정책 버전에서 생성합니다. 내부 메모, 직원 정보와 고객 개인정보는 공개 스키마 범위가 아닙니다.

## 5. 등급·사진·영상 제작 규칙

1. **등급:** 카테고리별 검사 항목, 허용 가능한 외관 손상, 예외·재검수 절차를 먼저 정의합니다. 등급명, 판정 임계값, 보증과의 관계는 **확정 필요**이며 이 문서에서 임의 등급을 만들지 않습니다.
2. **실사진:** 전체 모습, 카테고리별 필수 측면·구성품, 기록된 흠집, 필요 시 크기 비교 장면을 촬영합니다. 원본 기록에 실물 상품 ID와 촬영일을 연결합니다. 공개 시 개인정보·보안 위험이 있는 식별자는 가립니다.
3. **영상:** 실제 상품, 일반적인 상품화 과정, 콘셉트 장면을 구분해 표시합니다. AI 생성·변형 영상은 과정을 설명할 수 있으나 개별 상품의 상태·검수·세척을 입증하는 자료로 사용하지 않습니다.
4. **카테고리 확대:** 공통 필드에 카테고리별 필수 컷, 기능 검사, 설치 제약, 필요한 데이터 삭제 절차를 추가합니다. 체크리스트 책임자와 출시 기준은 **확정 필요**입니다.

## 6. PDP 신뢰 모듈과 콘텐츠 QA

제안하는 정보 순서는 상품·상태 요약 → 흠집을 포함한 실사진 → 검수·세척 → 보증·판매자·반품 → 배송·설치 → 구매 행동입니다. 최종 순서는 실제 화면과 사용자 검증 결과로 결정합니다.

게시 담당자는 다음을 확인합니다.

- 목록, PDP, 사진, 검수, 결제가 동일한 실물 상품 ID를 가리킵니다.
- 상태와 흠집 설명이 사진·검수 기록과 일치합니다.
- 검수 결과에서 합격·불합격·미검수를 구별하고 확인 범위를 넘어서지 않습니다.
- 세척·보증·반품·배송·설치 문구가 현재 승인된 조건과 일치합니다.
- AI 영상과 설명용 이미지는 실물 상태의 근거 자료와 구별됩니다.
- 필수 근거가 없으면 게시를 보류합니다. 수정 시 재검토하고 주문 당시 승인본을 보관합니다.

검토 책임자, 표본 검사 빈도, 예외 보고 경로, 처리 기한은 **확정 필요**입니다.

## 7. 측정·실험 명세

상태, 흠집, 검수, 세척, 보증, 배송 영역의 노출·열람과 결제 진입·구매를 연결해 관찰합니다. 제안 이벤트는 `trust_module_impression`, `trust_evidence_open`, `delivery_eligibility_result`, `checkout_entry`, `purchase`, `return_reason`, `support_reason`입니다. 각 이벤트에 상품·카테고리 키, 위치, 모듈 버전, 시각과 집계 단위를 기록하고 고객 개인정보는 넣지 않습니다.

실험은 대상 카테고리와 유입 조건을 고정한 처리군·비교군으로 설계합니다. 주요 성과, 반품·상담 증가 같은 방어 지표, 관찰 기간과 제외 규칙을 사전에 정의합니다. 바로 구매 또는 이벤트 반복이 가능하므로 원시 이벤트 합계를 순차 퍼널 전환율로 해석하지 않습니다. 세션·사용자·주문·상품 중 어떤 단위를 쓰는지 각각 문서화합니다. 목표치와 표본 크기는 **확정 필요**입니다.

## 8. 운영 적용 전에 필요한 결정

- 카테고리별 등급 기준과 검수 체크리스트 승인
- 보증·반품·판매 주체·배송·설치 조건과 담당자 확인
- 필드별 기준 시스템, 갱신 조건, QA 최종 승인자 지정
- 카테고리별 촬영·데이터 삭제 기준과 AI 영상 표시 문구 승인
- 실험 지표, 개인정보 보존 기간, 출시 기준 설정

포트폴리오 화면은 디자인 의도를 설명할 수 있습니다. 이 초안을 실제 운영 정책으로 사용하려면 관련 담당자의 결정과 상품별 근거 흐름의 구현·검증이 선행되어야 합니다.
